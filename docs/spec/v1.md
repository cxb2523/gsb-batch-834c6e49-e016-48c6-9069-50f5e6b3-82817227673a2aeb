# Spec v1: Lofi Lobby

The detailed design behind the [Architecture section of the README](../../README.md#architecture). Decisions in [ADR 001](../adr/001-one-durable-object-per-room.md) to [ADR 004](../adr/004-original-art-in-the-repo-local-assets-ignored.md).

## Flows

**Join.** The page loads the scene and shows "choose your trainer". The click on **enter the room** starts the radio (browsers need a gesture for sound). The client opens `wss://<host>/ws/<room>` and sends `hello { name, gender }`. The room answers `you { id }`, a `radio { command }` **snapshot** (its stored command or the default clock, with the room's duration table and `snapshot: true`), and `state { players }`; everyone else gets `joined`.

**Walk.** The client moves locally (collision runs on the client) and sends `pos { x, z, dir, step }` at most 15 times a second, only when something changed. Others interpolate toward the last position.

**Chat.** `chat { text }` → the room cleans it and sends `chat { id, name, text, at }` to everyone, sender included. The client adds it to the history and shows a bubble over the speaker for about 4 s (longer for long messages).

**Radio.** See [ADR 002](../adr/002-radio-synced-by-the-clock.md). The room's state is one command, `{ v, idx, at, rev, playlist, durations }`; it is enough for a client that joins or reconnects later to compute the same track and second as everyone (position = `now − at`, walked through the playlist with the real durations; unknown tracks fall back to one hour, and tracks a player reported as unplayable count as zero). Admin sends `radio { idx, password }`; on success the room builds a new command (`rev + 1`, `at = now`), stores it and broadcasts it; on failure it answers `error { msg }` to the sender only. A player that learned a track's real length sends `durations { id: seconds }`; the room validates the ids against its playlist, clamps the values, keeps the first report per id and broadcasts the retimed command (same `idx`/`at`, higher `rev`). A player that found a track unplayable sends `skip { id }`; the room adds it to the command's `skipped` list and broadcasts it, so every tab walks past the same track (an admin switch clears the list). On connect the room always sends its command as a snapshot, and the client lets that snapshot replace any cached command.

**Leave.** On close or error the room broadcasts `left { id }`.

## Protocol

JSON over WebSocket, documented at the top of [`worker/index.js`](../../worker/index.js). Field names are short and stable; the server validates every one.

| From client | Fields | Server checks |
|---|---|---|
| `hello` | `name`, `gender` | name cleaned to 16 chars; trainer is `male` or `female` |
| `pos` | `x`, `z`, `dir`, `step` | finite, within ±500; `dir` is `down`, `up`, `left` or `right`; `step` 0–3 |
| `chat` | `text` | cleaned to 140 chars; empty is dropped |
| `name` | `name` | as in `hello` |
| `gender` | `gender` | as in `hello` |
| `radio` | `idx`, `password` | constant-time password check; 5 failures per IP lock admin for 15 min |
| `durations` | `durations` (id → seconds) | only ids of the room's playlist; seconds clamped to 1 s–12 h; the first report per id wins |
| `skip` | `id` | only ids of the room's playlist; a repeat is a no-op; an admin switch clears the list |

## Radio command

```json
{
  "v": 1,
  "idx": 0,
  "at": 1767225600000,
  "rev": 3,
  "playlist": ["x6ujm9B-vAc"],
  "durations": { "x6ujm9B-vAc": 205.5 },
  "skipped": []
}
```

| Field | Meaning |
|---|---|
| `v` | Command version (1) |
| `idx` | Track in `playlist` where the timeline starts |
| `at` | Epoch ms when that track started (`rev` 0 with `idx 0` is the radio's default anchor) |
| `rev` | Grows on every admin action and every duration update; the higher revision wins on the client |
| `playlist` | The room's playlist, injected by the server (the cache and legacy commands fall back to the local list) |
| `durations` | Real track lengths in seconds; unknown tracks count as one hour |
| `skipped` | Tracks the room found unplayable (embed off / removed video); they count as zero-length, so everyone walks past them |

The same command object is what a late joiner or a reconnecting client receives (`snapshot: true` on connect), what is stored in the room object, and what `npm test` builds from made-up durations.

## Limits

| Limit | Value |
|---|---|
| Rooms | 1 (`lobby`); other names get 404 |
| Players per room | 100 |
| Message size | 1 KB |
| Rate (bucket size / refill per s) | pos 30 / 20 · chat 8 / 1 · other 10 / 1 |
| Name / chat | 16 / 140 characters |
| Connections per IP | 3 |
| Chat budget | shared by all connections of one IP |
| Spam (rate exceeded, or same text 4+ times in a row within 30 s) | warning → 15 s → 1 min → 5 min → 30 min mute; strikes reset after 30 min quiet |
